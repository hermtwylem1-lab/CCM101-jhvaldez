# Mission Reflection

This laboratory activity helped me understand the basic components of cloud infrastructure and how they work together. Among the different components, I think **compute resources** are one of the most important because they provide the processing power needed to run applications, services, and tasks. Without sufficient computing resources, cloud applications may not perform properly.

Linux supports cloud computing by providing a reliable environment for running and managing cloud servers. Through the KillerCoda Playground, I used Linux commands to check the operating system, kernel version, CPU, RAM, disk capacity, mounted file systems, hostname, and IP address. This gave me a better understanding of how Linux is used to manage and monitor cloud resources.

Technical documentation is important before deploying infrastructure because it provides a clear record of the system and its resources. It helps engineers understand the planned setup, identify possible problems, and maintain the infrastructure more easily. Good documentation also makes it easier for team members to communicate and work together.

During this laboratory activity, I learned how to use Linux commands to investigate a cloud server and identify its infrastructure components. I also learned how AWS, Microsoft Azure, and Google Cloud provide similar services under different names. In addition, I improved my Markdown writing, technical documentation, cloud infrastructure research, and GitHub management skills.

My GitHub portfolio improved because I added a new laboratory folder containing organized Markdown files, infrastructure reports, cloud provider comparisons, screenshots, and my reflection. This makes my portfolio more complete and shows my progress in learning cloud computing. Overall, this laboratory gave me practical experience in Linux, cloud infrastructure, research, and technical documentation.
